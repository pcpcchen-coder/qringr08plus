# QRing Studio 0.4.0：快照輪詢調校

日期：2026-10-12（Asia/Taipei）。新增介面讓使用者調整快照發送節拍與等待，測試實際回報瓶頸；不是宣稱已啟用戒指的高速原生串流。

## 原流程與三個設定

舊流程：送出 A1 03 快照，最多等新三軸取樣 0.35 秒，之後再休息 0.15 秒。0.15 秒只是輪後休息，不是完整的要求間隔。

「裝置與量測」頂部的「快照輪詢調校」新增三個設定，均允許 0–2 秒，滑桿步進 0.001 秒，亦可輸入數字。

| 介面 | 設定鍵 | 原預設 | 意義 |
| --- | --- | --- | --- |
| 快照發送節拍 | `accel_period` | 0 秒 | 每輪開始之間的最短間隔；0 盡快進下一輪 |
| 等待新取樣上限 | `accel_timeout` | 0.35 秒 | 發送後最多等多久；0 不等待取樣 |
| 取樣或逾時後休息 | `accel_interval` | 0.15 秒 | 收到資料或等到上限後休息多久；0 取消休息 |

每輪循序執行一次寫入。發送節拍不會覆蓋等待與休息；下一輪開始時間至少符合：

`本輪耗時 ≥ max(節拍, 寫入時間 + 實際等待時間 + 輪後休息)`

落後節拍時不補送一串積欠要求。三值為 0 時仍讓出事件迴圈，不建立多個並行寫入任務；實際速率由 BLE 寫入與系統排程決定，不能保證韌體能跟上。

## 使用方式

先輸入數值或選預設，再按「套用並儲存」。新設定於下一輪生效，最多需等目前輪次完成；已填入但未儲存的值不會被每秒狀態刷新覆蓋。套用時重置統計，設定保存在個人 `preferences.json`，保留原有觸控間隔與方向範圍。

| 預設 | 節拍 | 等待取樣上限 | 輪後休息 |
| --- | --- | --- | --- |
| 原設定 | 0 | 0.35 | 0.15 |
| 10 Hz 節拍 | 0.10 | 0.08 | 0 |
| 20 Hz 節拍 | 0.05 | 0.03 | 0 |
| 最快測試 | 0 | 0 | 0 |

要採完全不等回報的固定 10 Hz 目標，手動設節拍 0.1 秒、等待取樣上限 0、休息 0；20 Hz 對應節拍 0.05 秒。相關另見 [QRing Hand 的歷史觀察](2026-10-11-qring-hand.md)，該 App 的數字不能直接套用為 Studio 極限。

10／20 Hz 是目標節拍，不是保證的接收率。等待上限較短時，晚到或背景取樣仍可能被收到，不能把等待逾時當作要求已遺失。

未啟用輪詢時，套用參數不會自動開始感測；「開始快照輪詢」只啟用三軸，不啟用游標。若游標或校正已使用三軸，此設定也會影響它們。「停止快照與游標」停用加速度、游標與校正需求，其他獨立項目保留。停止後可能仍有先前已送要求或戒指自發通知到達，不宣稱韌體立即完全停止。

重新開啟 App 沿用參數，但游標與持續量測仍預設關閉。0.4.0 不改配戴／充電自動判斷，也不改游標中立停止、明確暫停及斷線守門。

## 實際統計的意義

- 實際送出、收到三軸、數值變化：最近 2 秒的事件計數除以窗口時間。剛重置時使用較短窗口；數值變化比較相鄰原始三軸值，第一筆不計為變化。
- 總送出／接收／變化數：自開始或重置起的累計。開始新一段輪詢、套用參數或按「重置統計」會建立新統計。
- 等待逾時：有實際等待的輪次才統計；設定上限 0 的輪次另列「不等待」，不算逾時。
- 平均等待：寫入完成後等待新取樣的時間，不是已配對的 BLE 往返延遲。
- 最後取樣年齡：直接由有效三軸通知接收的單調時間計算；沒收到取樣顯示「尚無取樣」，沒有把舊畫面讀值當作新回報。
- 最大取樣間隔：最近窗口內兩筆到達間的最大間隔。

有效三軸通知會包含重複值與可能的背景回報。協定沒有在此流程提供可驗證的一對一要求編號，因此接收率、數值變化率、等待逾時均不能直接當成硬體原生取樣率或掉包率。縮短等待也不等於改善感測器精度；耗電仍須另測。

## 驗證範圍

38 項 Python 與 12 項 JavaScript 測試通過，合計 50 項。新增檢查覆蓋節拍與休息的獨立時序、無回應時的等待上限、零等待循序寫入與事件迴圈可用性、窗口與重複值統計、偏好保存、非法數值拒絕、跨來源防護，以及重置時不混入先前等待結果。

獨立合成服務驗證預設套用、開始／停止、最快設定、未儲存編輯不被刷新覆蓋及重新載入。合成接收率只用於驗證介面與排程，不代表真實 R08 的極限。

0.4.0 封裝啟動回報 `BUNDLED_APP_SELF_TEST_OK`，完整簽章、bundle 版本與來源比對通過，已安裝至原有 App 路徑並確認原生介面。既有藍牙與控制權限重新指向同一安裝位置後，實機連線成功。保留原預設時，最近 2 秒接收約 4–5 筆三軸／秒；約 105.8 秒內共送出 453 次、收到 453 筆，有 2 次等待逾時。當時戒指三軸數值未變，這是到達率觀察，不能當成原生取樣率或極限測試。測試後停用快照與游標，保留原預設，個人校正與偏好檔內容一致。極限設定與長時間耗電仍為 `TBD / Needs device validation`，由使用者透過新介面測試。

程式、測試與本說明沿用專案的 Repo 進度交付方式；個人偏好、校正與完整私人封包不提交。
