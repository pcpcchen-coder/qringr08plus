## 安裝與使用

0.3.0 原始碼、測試與建置腳本已收錄在 Repo。建置後的 App 包含 Python 與相依套件，使用者不必另行安裝 Python 或 Homebrew；App 可複製至 ~/Applications/QRing Studio.app。0.3.0 二進位安裝包尚未發布 GitHub Release，請見 [建置產物說明](../releases/README.md)。先前交付的 QRing-Studio-0.2.0-arm64.dmg 屬舊版，不代表本次原始碼版本。

這是本機 ad-hoc 簽章開發版，未經 Apple 公證；跨電腦安裝與較舊 macOS 尚未測試。宣告最低版本為 macOS 13，CPU 為 arm64，不支援 Intel Mac。

1. 戴好戒指，讓手機 QRing 斷線，開啟 App 並按「連接戒指」。首次依 macOS 提示允許藍牙。
2. 「裝置與量測」顯示電量、充電狀態、硬體、韌體與序號；序號可能為空。
3. 「五步校正」進入後自動採樣；依序保持中立、右、左、上、下姿勢約 3 秒，頂部提示穩定後單擊戒指確認並進到下一步。五步完成後先測試方向，再單擊戒指儲存並返回主頁；滑鼠按鈕仍作備用操作。未穩定、方向不符、連擊或延遲重播事件不會跳步。
4. 返回「裝置與量測」，勾選「啟用 Mac 游標控制」。首次按「授權滑鼠控制」，在本機系統設定的「裝置控制和資料取用」允許 QRing Studio；舊系統可能稱「輔助使用」。
5. 滑鼠勾選後仍先暫停，長按切換移動／暫停；「立即暫停」可直接停住。取消勾選立即停止 App 的游標事件。
6. 確認移動可控後，可獨立勾選單擊左鍵。未實作拖曳、右鍵或捲動。
7. 需要量測的項目才勾選，也可按「量測一次」。關閉主視窗會隱藏視窗，App 留在選單列；從下拉選單「結束 QRing Studio」或按 ⌘Q 才會停止 App 任務、嘗試還原戒指設定並關閉服務。

### 選單列狀態與快捷操作

螢幕上方選單列常駐圖示與短文字，每約 0.5 秒更新。它與主視窗使用同一個 BLE 服務和控制狀態。

| 狀態 | 意義 |
| --- | --- |
| 未連線／關閉 | 戒指尚未連線，或未啟用 Mac 游標控制 |
| 暫停 | 已啟用，但暫停系統游標輸出 |
| 待命 | 控制已開始，資料正常，目前在中立死區 |
| 移動中 | 控制已開始，正在產生游標速度 |
| 延續移動 | 加速度資料間隙超過 0.35 秒，維持上一筆速度，收到新資料再更新 |
| 待資料 | 尚無可延續的速度，等待加速度資料 |
| 量測中 | 光學量測進行中，游標輸出暫停 |
| 需授權／服務離線 | 權限或服務不可用，不能控制游標 |

點擊選單列圖示，可顯示主視窗、開啟五步校正、啟用／停用游標控制、開始／繼續控制、立即暫停、切換單擊左鍵、連接／中斷戒指與結束 App。啟用游標後仍先暫停；從選單按「開始／繼續控制」或長按戒指才開始。權限、校正或連線未就緒時，相關操作不可用。左鍵點擊仍預設關閉。

勿同時執行舊版 ring_mouse.py、calibration_server.py 或其他戒指客戶端。本版 App 使用單一 BLE 連線，服務監聽 127.0.0.1:18765。

### 資料間隙與方向範圍

App 游標不再因 0.35 秒資料間隙自動停住；仍連線且控制已開始時延續上一筆速度，選單列顯示「延續移動」。收到中立姿勢立即歸零，長按／立即暫停／取消勾選／斷線停止；光學量測仍暫停輸出。啟用及重開 App 不會自動開始移動。舊獨立 CLI 的逾時停止預設保留。

「裝置與量測 → 滑鼠控制 → 校正後的方向範圍」可分別調整右、左、上、下容許偏差 2–60°，預設各 20°；中立停止區 0–20°，預設 8°。按「套用並儲存方向範圍」立即生效並在重開 App 後保留，不修改五步校正檔。範圍是目前正規化加速度向量與該方向校正取樣的夾角；範圍內沿該方向移動，重疊時選偏差最小的方向，範圍外保留自由傾斜移動。中立停止區優先，無效重力向量停止輸出；未落入任何方向範圍且距中立超過 60° 時停止，落入已設定方向範圍則照該方向移動。

畫面顯示判定方向、各方向的即時偏差及取樣資料年齡。未啟用游標時可勾選三軸加速度觀察。五步校正後的網頁測試採相同範圍與續移規則，不移動系統游標。保存方向設定會保留原先的觸控防重複間隔。

## 持續量測與省電

### 觸控防重複間隔

在「裝置與量測 → 按需量測 → 觸控防重複間隔（秒）」拖動滑桿或輸入 0–2 秒，按「套用並儲存」立即生效。預設 0.5 秒，0 秒代表關閉防重複；可一鍵恢復 0.5 秒。所有有效觸控仍會顯示事件回饋，間隔只限制重複執行滑鼠動作。

設定保存在這台 Mac 的 `~/Library/Application Support/QRing Studio/preferences.json`；重新開啟沿用間隔，游標、點擊及持續量測仍預設關閉。修改間隔不會中止手動健康測試。

所有 App 持續量測與滑鼠功能預設關閉，每次重新開啟都不自動恢復滑鼠。勾選加速度才輪詢 A1 快照；滑鼠或校正啟用時，因功能需要也會暫時讀取加速度與觸控，介面已說明這項依賴。

- 電量：連線時單次讀取；勾選後每 60 秒更新。
- 心率／血氧：只對勾選項目排隊量測，間隔可選 1、2、5、10 分鐘；每次最長 40 秒，收到有效非零值或配戴失敗即停止。光學量測不重疊；量測中暫停游標事件。
- 取消心率／血氧勾選：當次量測送 6A 停止指令，不排下一輪。
- 觸控：勾選、滑鼠或校正需要時才啟用回報；結束後還原原設定。
- 其他 BLE 通知：進階選項，只在勾選時訂閱其他 notify/indicate characteristic；不主動送出未知應用層指令。
- 未知資料即使由戒指自發送出，也會留下 RX 記錄；收到資料不表示 App 有啟動相應感測。

App 可以在連線時備份、暫停心率、血氧、壓力、HRV 的內建自動排程，並讀回驗證，離線時還原。**本韌體關閉內建心率排程後仍讀回原設定；因此只能保證 App 不主動啟動未勾選項目，不能保證戒指所有內部感測都停止。** 血壓、體溫與未知排程尚未接管，介面明確標示。

## 能力與訊息分類

App 內建 107 筆協定入口，區分 command / SPP 與量測候選；原廠／社群協定名稱不等於這顆戒指具有相應可用能力。

「能力探索」顯示本戒指既有實測與本次回應；唯讀查詢不會自動反覆執行。心率與血氧已取得非零回報，但沒有用參考醫療儀器驗證準確度。血壓、疲勞、綜合檢查、即時心率、壓力、血糖、HRV、體溫的 12 秒探測僅得到進度／未解碼值；不能據此宣稱功能不存在或有效量測完成。ECG 設定查詢被拒絕，尚未窮盡整個 ECG 家族。

未提供韌體更新、恢復原廠、關機或任意原始寫入。破壞性入口只列在探索清單，不提供執行。

「收發訊息」記錄 TX、RX（UUID、hex、校驗）、GATT、量測、解析、排程、設定還原與系統游標／點擊輸出。未知封包保留原文。加速度快照會附帶未解碼的其他通道，不為它們杜撰生理意義。

## 資料保存

使用者資料：~/Library/Application Support/QRing Studio/

- calibration.json：校正與速度；不包含在 App 安裝包。
- preferences.json：防重複間隔、四方向容許偏差及中立停止區；不包含在安裝包或 Repo。
- session-*.jsonl：每次執行的完整本機紀錄，可能包含健康資料。
- 畫面保留最近 1,000 筆，完整本次紀錄可透過原生存檔視窗匯出。
- 不自動上傳健康資料，不向公開 Repo 提交個人校正或原始健康紀錄。

持續高頻記錄會占用磁碟，目前不自動刪除舊紀錄；使用者可自行保留或移除自己的紀錄。

## 開發與打包

校正流程測試另需可執行 `node --test` 的 Node.js；封裝 App 不依賴 Node.js。

原始碼在此 mac-app/；native/Studio.swift 是 AppKit + WKWebView 容器，server.py 提供 loopback API，device.py 管理 BLE 與按需排程，ring_mouse.py 提供校正與游標映射。

開發環境需要 Apple Xcode 或 Command Line Tools 的 Python3.framework（3.9）、Swift、codesign，以及專案 .venv 的 requirements.txt 相依套件。打包腳本從執行中的 venv 自動取得 framework 與 site-packages 位置；原生容器仍固定使用內建 Python 3.9，不支援直接換成其他 Python 版本。

[M6 本機安裝與驗證紀錄](../docs/2026-10-09-m6-setup.md)

```sh
../.venv/bin/python -m unittest -v test_studio.py
node --test test_calibration.cjs
../.venv/bin/python build_app.py
../releases/.build.noindex/'QRing Studio.app'/Contents/MacOS/QRingStudio --self-test
```

build_app.py 包含 Python framework、site-packages、AppKit 執行檔及 UI。應用程式使用 Bundle 相對路徑、使用者 Application Support，不依賴開發者工作資料夾。內建 Python 停用 bytecode 寫入，避免修改已簽章的 bundle。

建置產物保存在 `releases/.build.noindex/QRing Studio.app`，避免與 `~/Applications/QRing Studio.app` 安裝版一起顯示於啟動區。舊版備份請使用 ZIP 封存，避免留下同名可啟動 App。

31 項 Python unit/API 測試涵蓋按需量測、停止條件、權限與跨來源檢查、候選結果隔離、事件回饋、偏好設定保存、方向範圍與資料間隙續移。另有 12 項 JavaScript 測試，驗證全程戒指單擊校正、就緒判斷、事件時效、隱藏分頁與斷線隔離，以及校正測試的方向範圍與續移。合計 43 項合成測試；不對真實戒指啟動量測或輸出滑鼠事件。封裝 self-test 啟動內建 Python/API、解碼選單列狀態並正常關閉。
[觸控事件回饋與健康候選測試結果說明](../docs/2026-10-10-ui-feedback.md)

M6 原生介面、控制與藍牙權限、連線及加速度取樣曾完成實機驗證；五步單擊完整流程另以合成資料驗證。方向手感、誤觸率、長期穩定性與耗電仍需佩戴測試。未將合成測試當作健康準確度驗證。

協定來源：[Halo-Ring 社群逆向文件](https://github.com/MRziyi/Halo-Ring/blob/main/Doc/09-r08-ble-protocol-spec.md)。社群實測使用不同韌體；本版的 verified-device.json 明確綁定本次實機版本且不含個人健康數值。

重新簽署的開發版可能使既有 macOS 權限對不上新版；更新後若無法控制或連線，先完整結束再重開，必要時在系統設定移除舊的 QRing Studio 項目，重新加入目前安裝位置。控制權限與藍牙權限分別檢查，不修改權限資料庫。
